# Задание
- Написать программу на языке C/C++ для перемножения двух квадратных матриц.
- Исходные данные: файл(ы) содержащие значения исходных матриц.
- Выходные данные: файл со значениями результирующей матрицы, время выполнения, объем задачи и др.
- Обязательна автоматизированная верификация результатов вычислений с помощью сторонних библиотек или стороннего ПО (например на Matlab/Python).
# Было реализовано:
Программа на языке С++ для перемножения 2х матриц и записи результата (l1.cpp — main, maker.cppm — модуль с функциями).
На вход программе подаются адресса двух файлов с перемножаемыми матрицами и один адресс файла для записи резульатов (l1 input/A.txt input/B.txt output/C.txt).
Перемножение осуществляется через перебор элементов вектора тройным циклом for. Значения записываются как тип double.  
В консоль выводится размер квадратной матрицы, длительность умножения матриц (в мс), количество операций сложения, 
среднее время выполнения одной операции сложения.  
Был написан скрипт l1.py на языке Python для верификации результатов вычислений с помощью сторонней библиотеки numpy. Он самостоятельно просматривает результаты 
выходных матриц C из папки output и сравнивает их с результатом перемножения матриц A и B. В консоль выводит размер матрицы и погрешность результатов программы
С++ относительно результатов, полученныъ-х с помощью библиотеки BLAS. В случае когда погрешность diff сильно отличается от допустимой tol, программа выводит
FAIL. Иначе ОК.

На маленькой матрице нет сильного расхождения с NumPy,
в отличие от матриц больших (~50 и более). Заменим diff = np.abs(C - C_ref).max() на  diff = np.abs(C - C_ref).max() / np.abs(C_ref).max() 
с целью приблизить ожидаемую погрешность к реальным результатам (вместо фиксированной погрешности, используется погрешность, величина которой теперь зависит
от размеров матрицы)  
  
output/C_5.txt: N=5, max diff = 3.891e-17 OK  
output/C_50.txt: N=50, max diff = 8.150e-07 OK  
output/C_100.txt: N=100, max diff = 1.515e-06 FAIL  
output/C_300.txt: N=300, max diff = 5.463e-07 OK  
output/C_500.txt: N=500, max diff = 3.424e-06 FAIL  
----------------------------------------------------------
  
Теперь погрешность меняется скачкообразно. Библиотека numpy при перемножении матриц с помощью оператора @ использует алгоритм BLAS. Он разбивает 
матрицу на микро блоки, помещающиеся в кеш-память, которые процессору удобно перемножать и суммировать. Суммирование элементов происходит в конце выпллнения
— накапление погрешности небольшое. В программе же, написанной на С++ используется простое суммирование с помощью тройного цикла for — погрешность 
накапливается быстрее (~N·ε, где ε ≈ 2.2e-16 — машинная точность double) => Погрешности от перемножения матриц через numpy и через тройной цикл расходятся с 
порядком ~2·N·ε (в теории). На практике этот показатель выше тк результат вычисления погрешности BLAS сравнивается с погрешностью тройного цикла, который 
случайно может оказаться как ближе к BLAS, так и дальше от него (из-за этого во втором вызове скрипта и появляются "скачки погрешности").  
# Вывод
Как итог, линейный метод перемножения матриц через тройной цикл for при оперировании большим объёмом входных значений выдаёт ошибочный результат из-за большого 
накопления погрешности. Алгоритм BLAS же, отличающийся разбиением матриц на отдельные блоки, параллельным их перемножением и результирующим суммированием значений,
даёт в разы меньшее значение погрешности.
